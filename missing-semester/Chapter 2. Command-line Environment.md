# Arguments
어제 만들었던 다양한 파이프를 통해서 어떠한 파이프라인을 만들었을 때 생각해야 하는 것은 이것들이 평행하게 작동을 한다고 생각을 해야 함. 단순히 일렬로 쭉~ 만들어지는 경우야 당연히 단순히 인풋 넣고 -> 아웃풋 나오는 흐름이기에 그렇게 보일 수야 있겠다만은, 그게 전부가 아니란 것임

예를 들어 파이썬으로 1초당 1씩 숫자를 내보내는 게 있음. 그러면 아무래도 `1 2 3 4 5 ...` 같은 아웃풋을 내보낼 것인데, 여기다 뒤에 파이프로 `| grep -P '(1|3|5|7|9)'`를 달았다고 생각하면, 단순히 앞에서 1부터 10 이상까지 숫자가 다 진행된 뒤에야 뒤에 있는 grep이 실행되는 게 아니라 앞에서 1 나오고 -> grep 돌고, 2 나오고 -> 돌고... 같은 형태기 때문에 시간이 흐름에 따라 숫자가 하나씩 나오게 되는 것임

자꾸 standard output, standard input, 뭐 이런 이야기를 하는데 이거는 알다시피 챕터 1에서 다룬 내용으로 인풋 / 아웃풋 / 에러 3종이 존재함. 

또한 어떤 걸 `/dev/null`로 보내면 그건 알아서 사라진다고. 그냥 약간 테스트 용도로 쓸 수 있는 형태인듯

# Customizing the Shell
어떤 프로그램에서는 tmux를 깔아야 함. 

근데 까는 것도 디스트로별 프로그램별 뭐 다 다름. brew, apt, 뭐 등등등... 
이런 걸 통해서 다양한 프로그램을 설치할 수 있음. 일반 grep보다 좀 더 편한 `ripgrep`이라든가...

PATH에 추가하기
PATH는 알다시피 우리가 가진 모든 프로그램이 있는 폴더를 의미함
`echo $PATH`로 알 수 있기도 하고, 아무튼 추가하고자 한다면 `export PATH="$PATH:path/to/append"`와 같은 형태로 새로운 폴더를 추가할 수 있음. export를 써야 child process에게도 적용이 가능

기본적으로 프로그램을 실행하고자 하면 무조건적으로 PATH를 찾고 지금 명령어가 실행되는 뭐 디렉토리를 살피진 않음. 

추가적으로 export로 무언가 env를 수정하고 child에게 줬다고 해도 이게 나갔다 들어오면 다 사라지게 됨. 

그래서 shell configuration 파일을 수정함을 통해서 이걸 조절을 해야 함. 이건 OS별 디스트로별 차이가 존재하니까 어딘가에 있는 config파일을 고쳐서 이걸 영구적으로 박을 수 있음 보통  bash_profile 파일이 홈 디렉토리에 있다는듯. 

dotfiles라고 사람들이 만든 자기만의 설정 파일을 (물론 자기가 저장하기 위함이지만) 올려둔 경우가 많음

그리고 어떤 프로그램, 뭐 이런 거를 컴퓨터를 옮겼을 때 커맨드로 알아서 후루룩 받게 할 수 있음.
그냥 dotfile을 심링크로 연결해서 다른 곳으로 연결하면 된다
